2. 전체 접근 방식

로봇 전체를 벡터로 다시 그리면 3D 렌더 느낌이 사라진다. 그래서 원본 래스터를 최대한 그대로 쓰고, 움직일 부분만 떼어 내 변형하는 컷아웃 방식을 택했다.

  1. 움직일 부분을 잘라낸다 — 팔(소매+커프+장갑), 부침개, 눈·볼 점.
  2. 잘라낸 자리를 메운다 — 팔이 내려가면 원래 가려져 있던 몸통·턱·화면 아래 가장자리가 드러난다. 이 부분을 복원하는 것이 작업의 대부분이었다.
  3. 원본에 없는 것은 벡터로 그린다 — 젓가락(오므리는 동작 때문에), 화면의 입, 부스러기, 김, 낙엽, 빛.
  4. SVG 안에서 변형한다 — 팔은 팔꿈치 기준 회전, 부침개는 팔 안에서 역회전+납작하게, 한입 자국은 mask로 처리한다.

핵심 확인 기준은 팔 각도 0°에서 원본과 픽셀 단위로 같아 보여야 한다는 것이다. 복원한 배경은 팔이 움직일 때만 드러난다.

3. 작업 환경에서 알게 된 것

  • 시스템 Python에는 PIL·OpenCV가 없었다. uv run --with pillow --with numpy --with opencv-python-headless python …로 설치 없이 실행했다.
  • dwebp, magick도 있었다. WebP→PNG 변환과 첫 크롭에 썼다.
  • Claude 데스크톱 앱의 브라우저 패널은 로컬 HTML을 data: 스냅샷으로 연다. 그래서 index.html이 상대경로의 SVG를 불러오지 못한다. SVG 파일을 직접 열어 확인했다(SVG가 이미지를 모두 내장하고 있어서 가능했다).
  • 이 패널의 screenshot zoom(영역 확대)은 지원되지 않는다. 대신 JS로 SVG의 viewBox를 잠시 좁혀 원하는 부분을 크게 봤다.

4. 단계별 과정

4-1. 좌표 측정

눈대중 대신 원본 좌표 격자를 덧그린 확대 크롭(보조 스크립트 grid.py: 20px 간격 선, 100px마다 다른 색, 좌표 라벨)을 만들어 보면서 폴리곤 좌표를 잡았다. 경계가 애매한 곳은 밝기값을 표로 출력해 정확한 위치를 찾았다. 화면 아래 가장자리 곡선이 그렇게 찾은 예다.

교훈: 3D 렌더 이미지의 곡선(화면 테두리 등)은 “기울어진 직선”으로 가정하면 틀린다. 결국 밝기값을 찍어 실제 곡선을 점으로 받아 적었다.

4-2. 마스크

대상방법메모
팔손으로 잡은 폴리곤 25점, 4배 슈퍼샘플링으로 안티앨리어싱(poly_mask)아래쪽은 접시 테두리를 따라 잘라, 회전할 때 테두리 조각이 딸려 오지 않게 했다.
젓가락두께 8px 직선 2개(line_mask)배경에서 지우는 데만 쓴다. 실제 젓가락은 벡터로 다시 그렸다.
부침개HSV 색 분할(H 8–35, S>135, V>110) → closing → 가장 큰 연결 성분 → 구멍 메우기처음 S>90으로 하니 복숭아색 조명을 받은 흰 테두리까지 잡혔다. 겹쳐 칠한 확인 이미지를 보고 알아냈다. floodFill로 구멍을 메울 때는 테두리를 1px 덧대야 모서리가 잘못 채워지지 않는다.
눈·볼 점밝기>110인 연결 성분을 가장 가까운 기준점(seed)에 배정하고, 그 스프라이트의 창 안에 완전히 들어오는 것만 채택뒤에 나오는 “시각 검증에서 잡은 버그” 참고.

4-3. 배경 복원 (가장 오래 걸린 부분)

메워야 할 곳은 팔 아래(몸통·어깨·턱), 부침개 아래(얼굴 화면 가장자리·흰 테두리), 젓가락 자리, 눈 자리다. 영역마다 방법을 다르게 썼다.

① 눈 지우기 — 어두운 화면 위의 밝은 눈은 Telea 인페인팅으로 쉽게 지워진다. 빛번짐까지 지우도록 14px 팽창한 마스크를 썼다. 눈은 나중에 스프라이트로 다시 얹는다. 잘 됨

② 몸통: 좌우 반전 복사 — 로봇 몸이 거의 대칭이라 오른쪽 몸(한복·위팔)을 반전해 왼쪽 빈자리에 넣었다.

  • 실패 얼굴이 약 12° 기울어 보여 기울어진 축으로 반사했더니, 중심축에서 멀어질수록 세로로 크게 밀려(200px 거리에서 약 90px) 소매 대신 배경이 들어왔다.
  • 해결 수직축 x=546으로 반사. 반전하면서 오른쪽의 “쉬고 있는 손”도 복사되지만, 내린 팔이 모든 각도에서 가려 준다.

③ 얼굴 화면 아래 가장자리와 흰 테두리

  • 실패 옆에서 띠를 밀어 복사: 원본 영역이 부침개와 겹치거나 볼 점이 딸려 왔다.
  • 실패 얼굴 전체를 기울어진 축으로 반사: 화면 가장자리 위치가 틀렸다.
  • 실패 Telea 인페인팅: 흰색이 검은 화면 쪽으로 번졌다(마스크 경계를 따라 흰 픽셀을 끌어옴).
  • 해결 화면 경계 곡선 E(x)와 턱 곡선 C(x)를 점으로 직접 정의했다. E 위쪽(검은 화면)과 E~C 사이(흰 외피)를 각각 같은 색 영역의 알려진 픽셀만으로 채웠다(nc_fill: 정규화 컨볼루션). 두 채움은 clip(y − E(x) + 0.5) 가중치로 안티앨리어싱 합성하고, C 아래는 반전 몸통에 턱 그림자(최대 28%)를 얹었다.

④ 어깨 외곽 — 반전한 소매가 팔 폴리곤 경계에서 직선으로 잘려 보였다. 둥근 어깨 폴리곤(SHOULDER) 밖은 단풍 배경으로 채웠다.

  • 실패 다중 스케일 nc_fill로 단풍을 채우니 동심원 띠가 생겼다 → 채도 높은 단풍 픽셀만 참조하는 Telea로 교체.
  • 실패·되돌림 “반전 픽셀이 단풍색이면 배경으로 처리”하는 판별: 따뜻한 조명을 받은 소매를 단풍으로 오인해 구멍이 났다.

⑤ 남은 곳 — Telea로 채운 뒤, 구멍 경계만 가우시안으로 블렌딩해(feather_comp) 원본과 이었다.

교훈: 한 가지 인페인팅으로 다 하려 하지 말고, 영역의 성격(대칭 구조 / 단색 면 / 경계선 / 배경 질감)에 따라 방법을 나눈다. 색이 다른 두 면이 맞닿은 곳은 경계선을 직접 정의하고 면마다 따로 채워야 번지지 않는다.

4-4. 전경 레이어

  • arm.png: 팔 마스크를 알파로 한 RGBA 크롭(270,540)–(490,760).
  • jeon.png: 부침개 위를 가로지르던 젓가락 픽셀을 부침개 픽셀만으로 인페인팅해 지웠다(새 젓가락은 벡터로 앞에 그림).
  • eyeL/eyeR/dotL/dotR.png: 부드러운 알파의 빛 스프라이트. RGB는 “자기 빛번짐만 남기고 다른 눈은 지운 이미지”에서 잘랐다. 박스는 알파가 0이 되는 지점까지 넓혔다.

4-5. 동작 설계와 미리보기

SVG를 만들기 전에 Python 합성기(preview.py)로 팔 각도 0°/20°/40°와 집는 자세를 정지 이미지로 렌더해 확인했다.

  • 팔꿈치 회전축 PIV=(300,705), 40° 회전하면 부침개 중심이 (572,542)에서 (613,755)로, 즉 접시의 부침개 더미 위로 간다.
  • 집는 순간 들고 있는 부침개가 더미와 똑같이 보이도록, 팔 회전을 상쇄하는 역회전과 세로 0.52배 납작하게를 적용했다. 접시에 부침개를 따로 복사해 두지 않고, 들고 있는 부침개를 집는 순간 서서히 나타나게 했다.

4-6. SVG 조립

레이어 구조(아래에서 위로): 배경 → 달·등불 빛 → 김 → 눈(그룹) → 볼 점 → 입 → 팔 그룹[아래 젓가락 → 부침개 → 위 젓가락 → 팔 래스터] → 부스러기 → 낙엽.

<g id="arm"> rotate(a, 300, 705)
  <g> rotate(pinch, 430, 585)  아래 젓가락 </g>
  <g transform="translate(572 542)">
    <g> rotate(-a)                     ← 팔 회전 상쇄
      <g> scale(1, s)                  ← 접시 위에서 납작하게
        <g transform="translate(-572 -542)" mask="url(#bite)"> opacity, jeon.png </g>
  위 젓가락, arm.png
</g>
  • SMIL은 요소 하나당 transform 애니메이션이 하나만 적용되므로, 변형마다 <g>를 하나씩 중첩한다.
  • 모든 애니메이션은 dur="8s" repeatCount="indefinite"를 공유하고 keyTimes로 시점을 맞춘다. 헬퍼 kf()/at()가 (시간, 값, 이징) 목록을 values·keyTimes·keySplines 문자열로 바꾼다.
  • 한입 자국: mask 안의 검은 원의 r을 calcMode="discrete"로 0→R로 바꾸고, 부침개가 안 보이는 4.0s에 0으로 되돌린다. discrete에서는 마지막 keyTime이 1이 아니어도 된다.
  • 입: 원본에는 입이 없어 새로 추가했다. 벌린 입 / 씹는 입(ω 모양, 세로 스케일 진동) / 미소 세 가지를 opacity로 전환하고, 파란 빛 필터(#glow)를 준다.
  • 분위기 효과: 떡국 김(블러 처리한 선이 올라가며 사라짐), 단풍잎 6장(animateMotion + 회전 + 좌우 스케일 뒤집기), 등불·달 빛(mix-blend-mode:screen).

6. 검증 방법

  1. 정지 합성: preview.py로 0/20/40°와 집는 자세 확인. 팔을 든 자세가 원본과 같은지 확인.
  2. SMIL 구조 검사: XML을 파싱해 values·keyTimes 개수, keySplines 개수(= keyTimes − 1), 증가 순서를 확인.
  3. 브라우저 상태 검사: svg.pauseAnimations() + svg.setCurrentTime(t) 후 getCTM()으로 팔 각도, getComputedStyle().opacity, circle.r.animVal을 읽어 타임라인과 비교.
  4. 시각 검사(사용자 허락 후): 같은 방식으로 시점을 고정하고, viewBox를 좁혀 부분 확대 → 스크린샷.

시각 검증에서 잡은 버그

눈 스프라이트 잘림 — 눈이 아래를 볼 때(4.2s) 눈 끝이 잘리고 원래 눈 자국과 사각형 테두리가 보였다. 원인은 고정 박스가 실제 눈과 빛번짐보다 작았던 것. 연결 성분 기반으로 바꾸고, 알파가 0이 되는 지점까지 박스를 넓혀 해결했다. 이 과정에서 두 번 더 실수가 있었다. 흰 외피가 “눈”으로 잡혀 박스가 커졌고, 볼 점 옆의 화면 테두리도 잡혔다. 스프라이트별 창 안에 완전히 들어오는 성분만 받도록 해서 해결했다.

낙엽이 별처럼 보임 — 30px짜리 뾰족한 도형이라 빨간 별로 읽혔다. 50–60px, 잎자루·잎맥·그라데이션, 좌우 스케일 뒤집기로 팔랑임을 넣어 해결. linearGradient의 objectBoundingBox 좌표는 0–1이다(−1로 썼다가 고침).

교훈: 좌표·상태 검사만으로는 “움직였을 때 드러나는 이음새”를 못 잡는다. 정지 상태에서 완벽해도 스프라이트가 움직이면 박스 경계와 지우다 남은 자국이 보인다. 움직이는 모든 스프라이트는 가장 멀리 이동한 시점에서 확대해 봐야 한다.

7. 비슷한 작업 체크리스트

  1. 도구 확인: Python 패키지가 없으면 uv run --with ….
  2. 움직일 부분을 정하고, 회전축·이동 범위를 먼저 계산한다(예: 40° 회전하면 끝점이 목표에 닿는가).
  3. 좌표 격자 크롭으로 폴리곤을 잡는다. 애매한 경계는 밝기값을 찍어 본다.
  4. 색 분할 마스크는 반드시 겹쳐 칠해 확인한다(조명을 받은 흰색이 쉽게 섞인다).
  5. 드러날 영역을 성격별로 나눠 복원한다: 대칭 → 반사(축은 실측, 기울기 가정 주의), 단색 면 → 같은 색끼리만 채움, 두 면의 경계 → 곡선을 직접 정의, 배경 질감 → Telea.
  6. 기준 자세에서 원본과 같은지 확인한다.
  7. 극단 자세들을 정지 합성으로 미리 본다.
  8. SVG: 변형마다 <g> 중첩, 공통 dur + keyTimes, 사라지는 것은 mask + discrete, 반복 경계(t=0 = t=T)의 연속성 확인.
  9. 브라우저에서 setCurrentTime으로 상태를 검사하고, 움직이는 스프라이트는 최대 이동 시점에서 확대해 본다.
  10. 원본에 없는 요소(여기서는 입, 효과)는 목록으로 남겨 사용자에게 알린다.

이 문서의 좌표는 모두 원본 1536×1024 픽셀 기준이다.
